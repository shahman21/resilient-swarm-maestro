# Leap Motion 控制 mBot2 与网页：完整操作流程

本模块放在 `integrations/leap_usb/`，保留团队原来的服务器和主网页。它是单独启动的 USB 演示入口，不需要运行原来的 hub，也不需要机器人连接 Wi-Fi。

## 1. 准备设备与软件

- 一台 Windows 电脑、mBot2（含童芯派）、Leap Motion Controller 2、两条可传数据的 USB 线。
- 64 位 Python；你目前电脑的 Python 3.13.9 已经能运行 Leap 读取脚本。
- mBlock 桌面版；你目前使用 5.6.0。
- Ultraleap Tracking 与 SDK：打开 Control Panel，确认设备为 Leap Motion Controller 2、Tracking Active，手在上方时能看到骨架。建议 Desktop 模式。
- 本包不含厂商驱动和 LeapC.dll，需使用电脑上安装的软件提供的文件。无需 pip 安装依赖。

## 2. 连线

1. Leap USB 连接电脑。
2. 童芯派 USB 连接同一台电脑，底盘电源打开。
3. 打开 mBlock，设备选择“童芯派”，点击“连接”选择对应串口。
4. 模式选择“在线”。之后保持连接，两条 USB 线都保留。

## 3. 搭建 mBlock 程序

添加“mBot2 底盘”扩展，在“事件”中取键盘事件，在“控制”取等待积木。建立四组互相独立的积木：

| 事件积木 | 下面依次连接 |
|---|---|
| 当按下 W 键 | 前进，以 30 RPM → 等待 0.2 秒 → 停止编码电机，全部 |
| 当按下 A 键 | 左转，以 30 RPM → 等待 0.2 秒 → 停止编码电机，全部 |
| 当按下 D 键 | 右转，以 30 RPM → 等待 0.2 秒 → 停止编码电机，全部 |
| 当按下空格键 | 停止编码电机，全部 |

选择带 RPM 的运动积木；先不要更改速度与时间。本包提供 Python 与网页源码，mBlock 项目需要按表搭建，未附带 `.mblock` 工程。

先将轮子架空，点击 mBlock 积木区空白处，用真实键盘分别按 W、A、D 和空格。必须先确认实体车响应。保存 mBlock 项目，下一次可直接打开。

## 4. 启动整套程序

1. 下载整个模块并解压。不要在 ZIP 内运行，也不要只下载其中一个 Python 文件。
2. 旧的 Leap 脚本如果仍在运行，在其黑色命令窗口按 Ctrl+C 停止。
3. 进入 `integrations/leap_usb/`，双击 `START_WINDOWS.bat`。
4. 浏览器应自动打开 `http://127.0.0.1:8765`。未打开则手动输入。不要双击 HTML，也不要打开旧的 8000 端口。
5. 先设置网页音乐与视觉选项，再将浏览器和 mBlock 并排显示。最后点击 mBlock 的空白积木区，保持它为当前活动窗口。
6. 一只手掌心朝下，在 Leap 上方水平保持约半秒，完成校准。

## 5. 手势操作

| 你做的动作 | 小车动作 | 网页变化 |
|---|---|---|
| 手掌水平 | 向前移动 | 前进指令与估算轨迹 |
| 手掌左侧压低超过约 30° | 左转 | 左转指令、角度与估算方向 |
| 手掌右侧压低超过约 30° | 右转 | 右转指令、角度与估算方向 |
| 回正到约 15°以内 | 恢复前进 | 恢复前进显示 |
| 握拳或移开手 | 停车 | Stop |

用倾斜角度控制，不是把整只手向左右平移。手指可以轻微弯曲，明显握拳才停车。控制为重复的短动作，沿用当前 0.2 秒的 mBlock 动作。

点击网页或聊天窗口会让 mBlock 失去焦点，程序不再发新运动键；已开始的短动作可能运行至 0.2 秒结束。回到 mBlock 空白处，再次平放手掌校准后继续。退出程序用 Escape，或在命令窗口按 Ctrl+C。必要时直接关闭底盘电源。

## 6. 命令行运行与排错

在模块文件夹空白处点击资源管理器地址栏，输入 `cmd` 并回车。以下命令输入黑色命令窗口，不要先单独输入 `py`。如果已经看到 `>>>`，输入 `exit()` 并回车退出 Python 交互环境。

正常启动：

```bat
py leap_sync.py
```

DLL 路径不正确：

```bat
py leap_sync.py --dll "D:\leap motion\Ultraleap\LeapSDK\lib\x64\LeapC.dll"
```

其他电脑需将引号内替换为其实际 DLL 路径。查找例子：

```bat
where /r "D:\leap motion" LeapC.dll
```

左右相反：

```bat
py leap_sync.py --invert-roll
```

端口被占用：关闭旧程序，或：

```bat
py leap_sync.py --port 8766
```

随后访问 `http://127.0.0.1:8766`。

测试模拟键盘是否到达 mBlock：

```bat
py leap_sync.py --test-key
```

回车后五秒内切到 mBlock，点击其空白区域；应产生一次前进。测试左转用 `--test-left`。若终端提示 `NOT SENT`，说明倒计时结束时前台不是 mBlock。

| 现象 | 处理 |
|---|---|
| Python 找不到文件 | 确认在 `leap_usb` 文件夹运行命令 |
| 找不到 LeapC.dll | 用 `--dll` 指向实际 SDK x64 DLL |
| 32/64 位相关错误 | 使用 64 位 Python 与 x64 DLL |
| No hand | 查看 Ultraleap Control Panel 骨架，确认 Tracking 正常 |
| Calibrate | 手掌朝下保持水平，不要一开始就倾斜 |
| 网页动但车不动 | 先用真实键盘测试 mBlock，确认在线连接和底盘电源 |
| 切换网页后不动 | 点击 mBlock 空白处，再平放手掌校准 |
| 左转识别成右转 | 退出后使用 `--invert-roll` |
| 网页等待 bridge | 确认启动的是本模块 `leap_sync.py`，而非旧脚本 |

## 7. 同步范围与局限

一份 Leap 数据生成同一组方向指令，同时供 mBlock 和网页使用。网页中的主车位置根据已发送按键估算，**不是实体小车的定位数据**；本模块没有读取车轮编码器回传，也没有视觉定位。实体车实际是否执行按键没有返回确认。

原页面音乐、群体排列、背景统计是演示视觉。USB 状态条是本控制进程数据。“连接”不等于小车位置回传。地面、电量、打滑和 USB 延迟都会导致路线偏差。更改积木速度或 0.2 秒时间后，要同时调整 `local_sync.py` 估算参数。

## 8. 给队友的启动说明

在仓库根目录打开命令行：

```bat
cd integrations\leap_usb
py leap_sync.py --dll "你电脑的LeapC.dll完整路径"
```

无需启动根目录原 hub。团队主网页之后若更新，这个独立副本不会自动同步。后续统一到主 hub 时，可复用手势判断和 `/api/control_state` 数据结构，由团队按实际服务器接口接入。
